# GoldLot2L Platform Blueprint v0.1

วันที่ร่าง: 11 พ.ย. 2026 | สถานะ: ร่างหลังการปรึกษา (ยังไม่เริ่มพัฒนา)
Repo ปัจจุบัน: vhpknn/GoldLot2L (PWA แบบ static: index.html, report.js, sw.js, manifest.json)
หมายเหตุ: เอกสารนี้เป็นแผนทางเทคนิค ไม่ใช่คำปรึกษากฎหมาย/ภาษี/การลงทุน

---

## 0. สรุป 1 หน้า

GoldLot2L จะเปลี่ยนจากแอปบันทึกทองคนเดียว เป็นแพลตฟอร์ม "สมุดบันทึกสินทรัพย์ส่วนตัว" ที่
- รองรับหลายสินทรัพย์ หลายหมวด หลายประเทศ หลายภาษา
- ปรับหน้าตาและความซับซ้อนตามอายุ/ระดับผู้ใช้ (เด็ก 13-15 ถึงผู้สูงอายุ ถึงผู้ใช้ขั้นสูง)
- ข้อมูลธุรกรรมอยู่ในเครื่องผู้ใช้ (local-first) สำรองเข้ารหัสไป Google Drive / OneDrive ของผู้ใช้เอง
- เซิร์ฟเวอร์เก็บเฉพาะบัญชี สิทธิ์สมาชิก และ config
- ขยายฟีเจอร์ผ่านโมดูล (add-on) ภายในแอปเดียว (modular monolith)
- มีระบบสมาชิก 4 Tier, หน้า admin, อัปเดตอัตโนมัติแบบปลอดภัย

จุดยืนผลิตภัณฑ์: เป็น "สมุดบันทึกและสถิติ" ตามกฎที่ผู้ใช้ตั้งเอง ไม่ใช่คำแนะนำการลงทุน

## 1. หลักการออกแบบ (Design Principles)

1. สมุดบันทึก ไม่ใช่ผู้แนะนำ: ข้อความทุกจุดต้องเป็นกลาง ("ถึงเงื่อนไขที่คุณตั้งไว้")
2. Local-first: ใช้งานได้ออฟไลน์ ข้อมูลเป็นของผู้ใช้ ส่งออกได้เสมอ
3. สองแกนแยกกัน: สิทธิ์ที่จ่าย (Tier) ต่างจากความซับซ้อนที่เลือก (Complexity Level)
4. ทุกอย่างเป็นข้อมูล/โมดูล ไม่ฝังในแกนกลาง (ธีม ภาษา ป้ายข้อความ สินทรัพย์ แพ็กเกจ)
5. ปลอดภัยก่อนฟีเจอร์: แก้ XSS, สำรองข้อมูล, ไม่ล็อกข้อมูลผู้ใช้เมื่อหมดสมาชิก
6. เริ่มเล็ก ทยอยขยาย ย้อนกลับได้ทุกเฟส (branch แยก, สำรองก่อนแก้)

## 3. สถาปัตยกรรมภาพรวม

```
[ผู้ใช้: PWA / Android(TWA) / (iOS PWA) / (WhatsApp แจ้งเตือน)]
        |  (ข้อมูลธุรกรรมอยู่ในเครื่อง: IndexedDB)
        |--- Storage Adapter ---> local | Google Drive appDataFolder | OneDrive AppFolder
        |
   HTTPS API (Express)
        |-- Auth / Accounts
        |-- Entitlement Resolver  <-- Subscriptions (Stripe webhook)
        |-- Config: plans, limits, assets, categories, themes, labels, country_rules
        |-- Reference data: suggested ATH, festival themes (versioned)
        |-- Admin API
        v
   PostgreSQL (บัญชี/สิทธิ์/config เป็นหลัก)
```

หน้าที่ของแต่ละชั้น
- Client: คำนวณ grid (analyze) เก็บธุรกรรม แสดง UI ตาม CL + Theme + ภาษา
- Server: ยืนยันตัวตน ออกใบอนุญาต (signed entitlement token) เสิร์ฟ config/ข้อมูลอ้างอิง ไม่เก็บธุรกรรมละเอียด (ยกเว้นเฟสซิงก์ในอนาคต)
- CDN/Cloudflare: เสิร์ฟ static, WAF, rate limit

## 4. สี่แกนของผู้ใช้

| แกน | ควบคุมอะไร | ใครกำหนด |
|---|---|---|
| Tier 1-4 | ฟีเจอร์/โควตาที่จ่ายเงิน | ซื้อ (admin ตั้งค่าได้) |
| Complexity Level (CL) 1-5 | ฟีเจอร์ที่เห็นและความง่ายของภาษา | ผู้ใช้เลือก ค่าเริ่มต้นตามวัย |
| Theme | สี ฟอนต์ ไอคอน ขนาดปุ่ม | ผู้ใช้เลือก ค่าเริ่มต้นตาม Persona |
| Persona | ชุดค่าเริ่มต้นของ CL+Theme (เด็ก / ผู้สูงอายุ / ทั่วไป / ขั้นสูง) | ระบบแนะนำจากอายุ ผู้ใช้เปลี่ยนได้ |

### 4.1 Tier (ค่าเริ่มต้น ปรับได้ใน admin)

| Tier | ทุนรวมสูงสุด | ราคา/เดือน | จำนวนสินทรัพย์ | ตัวอย่างสิทธิ์ |
|---|---|---|---|---|
| 1 | 999 USD | ฟรี | 1 | เฉพาะ Layer 1 |
| 2 | 9,999 USD | 3 USD | 3 | ตั้งค่าใน admin |
| 3 | 99,999 USD | 9 USD | 5 | ตั้งค่าใน admin |
| 4 | ไม่จำกัด | 20 USD | ไม่จำกัด | ตั้งค่าใน admin |

กติกาเมื่อเกินเพดานทุน: เตือนให้อัพเกรด + ล็อกการ "เพิ่มไม้ใหม่" แต่ยังดู/ขาย/ส่งออกข้อมูลเดิมได้
กติกาเมื่อ downgrade: ข้อมูลไม่หาย สินทรัพย์เกินโควตาเป็นแบบอ่านอย่างเดียว ให้ผู้ใช้เลือกสินทรัพย์ที่จะคงไว้
ทุกแผนส่งออกข้อมูลของตัวเองได้เสมอ

Capability keys ตั้งต้น: max_assets, max_capital, layers_allowed, snowball, report, export_csv, notifications, custom_labels, themes_allowed, auto_backup, multi_device_sync, sheet_price_link, modules_allowed

### 4.2 Complexity Level

| CL | เห็นอะไร | ตัวอย่างผู้ใช้ |
|---|---|---|
| 1 | บันทึกง่ายสุด หน้าเดียว "ถึงเป้าหรือยัง" ภาษาธรรมดา ไม่มี ATH/Layer | เด็ก, ผู้สูงอายุ, มือใหม่ |
| 2 | + ประวัติ + ยอดรวม | |
| 3 | + 2 Layer + ตั้งค่าพื้นฐาน | ผู้ใช้ทั่วไป |
| 4 | + Snowball + ปรับทุน + รายงาน | |
| 5 | ทุกฟีเจอร์ + พารามิเตอร์ขั้นสูง + stress test | ผู้ใช้ขั้นสูง |

CL ซ่อน/แสดงการ์ด (data-cl) ไม่ลบข้อมูล สลับได้ทันที "ซ่อนตาม CL" ต่างจาก "ล็อกตาม Tier"

### 4.3 Persona -> ค่าเริ่มต้น
- เด็ก 13-15: CL1, ธีมสดใส, ปุ่มใหญ่, เป้าหมายการออม/ความคืบหน้า, ตัดศัพท์ ATH/Layer/Snowball, ต้องมีผู้ปกครองอนุมัติ
- ผู้สูงอายุ 60-80: CL1, ธีม minimal คอนทราสต์สูง, ฟอนต์ >= 16pt ปรับได้ถึง 200%, พื้นที่กด >= 44x44pt, เมนูตำแหน่งคงที่, ไม่พึ่งสีอย่างเดียว (เพิ่ม ▲▼ และข้อความ กำไร/ขาดทุน)
- ทั่วไป: CL3 ธีมมาตรฐาน
- ขั้นสูง: CL5

เก็บ birth_year (ไม่เก็บวันเกิดเต็ม) ใช้แนะนำค่าเริ่มต้นเท่านั้น ไม่ล็อกผู้ใช้

## 6. ระบบโมดูล (Add-on)

รูปแบบ: modular monolith ที่โค้ดเดียว deploy เดียว แต่ขอบเขตโมดูลชัด คุยกันผ่าน interface

Core ให้ API แก่โมดูล: getState(), registerCard(), registerSetting(), registerRoute(), can(capability), t(key, vars), storage (ผ่าน Storage Adapter)

manifest.json ของโมดูล (ตัวอย่าง)
```
{
  "id": "stress-test",
  "version": "1.0.0",
  "coreApi": ">=1.0 <2.0",
  "name_i18n": {"th": "จำลองราคาตก", "en": "Price drop simulator"},
  "capabilities": ["stress_test"],
  "minCL": 5,
  "extensionPoints": ["card:home", "route:/stress"],
  "storage": "own-namespace"
}
```

โมดูลตั้งต้น: core-journal (แกนบันทึก), grid-engine, assets-market, assets-manual, assets-loan (เฟส 2), report, themes, notifications, backup, price-sheet-link, stress-test, persona-kids, persona-seniors
กฎ: ไม่เปิดให้บุคคลที่สามเขียนโมดูลในเวอร์ชันแรก (ถ้าอนาคตเปิด ต้องรันใน iframe sandbox และมีการตรวจสอบ)

## 7. สินทรัพย์ ราคา และ ATH

### 7.1 ชนิดสินทรัพย์ (asset.kind)
| kind | ตัวอย่าง | ลักษณะ |
|---|---|---|
| market | ทอง, น้ำมัน, S&P500, NAS100 | มีราคา ATH ใช้ Grid |
| manual | ของสะสม, ทองที่ซื้อเอง | ผู้ใช้กรอกราคาเอง |
| loan | ให้ยืมเงิน | ลูกหนี้ เงินต้น ดอกเบี้ย กำหนดคืน (เฟส 2) |
| savings | กระปุกออม | เป้าหมาย/ความคืบหน้า (เหมาะ CL1) |

asset_config ต่อสินทรัพย์: สกุลเงิน, หน่วย (บาททอง/ออนซ์/หุ้น/ลอต), ทศนิยม, ขั้นต่ำ, โหมดราคา (Bid/Ask แยก หรือราคาเดียว)

### 7.2 Price Provider (3 โหมดในเฟสแรก)
1. manual: ผู้ใช้กรอกเองในตั้งค่า (มีผลสูงสุด)
2. sheet_csv: ผู้ใช้ทำสำเนาเท็มเพลต Google Sheet ที่ใช้ GOOGLEFINANCE แล้ว publish เป็น CSV แอปอ่านลิงก์นั้น
3. suggested: ค่า ATH แนะนำจากระบบ แสดงพร้อมแหล่งที่มา/วันที่ ผู้ใช้กดยอมรับ

ลำดับความสำคัญ: ผู้ใช้กรอก > ชีตที่ผูก > ค่าแนะนำ

ข้อเท็จจริงที่ต้องจำ
- ไม่มี Google Finance API อย่างเป็นทางการ ฟังก์ชัน GOOGLEFINANCE ใช้ได้ในชีตเท่านั้น
- ข้อมูลย้อนหลังจากฟังก์ชันนี้ดึงออกนอกชีตผ่าน API ไม่ได้ จึงเสี่ยงสำหรับการหา ATH ต้องทดสอบจริงว่าเซลล์ MAX อ่านออกมาได้หรือไม่ ก่อนพึ่งพา
- ข้อมูลหน่วงได้ราว 20 นาที ชีตไม่รีเฟรชเองถ้าไม่มี trigger
- OAuth ของ Sheets API เป็น sensitive scope ต้องผ่านการตรวจสอบ จึงเลื่อนเป็นเฟสหลัง

กติกาความปลอดภัยของ ATH
- ถามก่อนเปลี่ยน ATH เสมอ (ยกเว้นผู้ใช้เลือกโหมดอัตโนมัติ)
- sanity check: เตือนเมื่อต่างจากเดิมเกิน 20%, ปฏิเสธค่า 0/#N/A/ว่าง, ไม่เขียนทับเมื่ออ่านไม่ได้
- แสดงสถานะ "ข้อมูลเก่า" และเก็บประวัติการเปลี่ยน ย้อนกลับได้
- โหมด ATH: อัตโนมัติ (MAX ตลอดประวัติ) / กำหนดเอง / หน้าต่างเวลา N ปี

Provider ภายนอก (API ที่มีสัญญา) เป็นโมดูลเฟสหลัง ต้องตรวจสิทธิ์เผยแพร่ข้อมูลต่อก่อนใช้

## 8. ประเภท loan (เฟส 2)
- counterparties(id, nickname, note) ใช้ชื่อเล่นได้ เก็บข้อมูลบุคคลที่สามให้น้อยที่สุด
- loan_entries(id, counterparty_id, type[lend|repay_principal|repay_interest], amount, date, note)
- สถานะคำนวณ: เงินต้นค้าง, ดอกเบี้ยรับแล้ว, ทุนว่างจริง, วันครบกำหนด
- ตัวอย่าง: ทุน 100 ให้ A ยืม 50 ให้ B ยืม 50 A คืน 55 (ต้น 50 + ดอก 5) => กำไรดอกเบี้ย 5
- เก็บดอกเบี้ยรวมและช่วงเวลา เพื่อคำนวณอัตราต่อปีได้
- ขอบเขต: สมุดบันทึกส่วนตัว ไม่ส่งข้อความทวงหนี้แทนผู้ใช้

## 9. ภาษา ประเทศ สกุลเงิน (i18n)
- ข้อความ UI ทั้งหมดเป็น key (เช่น today.sell_ready) เรียก t(key, vars) ไฟล์ภาษาแยกตามฟีเจอร์ มี fallback เป็นอังกฤษ
- ใช้ Intl API จัดรูปแบบตัวเลข/วันที่/สกุลเงิน แทน toLocaleString('th-TH') และ dshow() ที่ตายตัว
- ค่าเริ่มต้นภาษา: ภาษาเบราว์เซอร์ -> ที่ผู้ใช้เลือกเอง -> IP เป็นทางสำรอง
- ผู้ใช้ตั้งอิสระ 3 อย่าง: ภาษา, ประเทศ/ภูมิภาค(รูปแบบวันที่ตัวเลข), สกุลเงินแสดงผล
- รองรับ RTL: ใช้ CSS logical properties (margin-inline-start ฯลฯ) และ dir="rtl" ต้องไล่แก้ text-align:left / border-left ใน index.html
- ข้อความกฎหมาย (disclaimer) ล็อก แก้ไม่ได้ และต้องแปลโดยผู้เชี่ยวชาญ
- country_rules เก็บอายุขั้นต่ำ/ผู้ปกครอง/ภาษา/สกุลเงินต่อประเทศ เปิดประเทศทีละกลุ่ม

### 9.1 ป้ายข้อความที่ผู้ใช้กำหนดเอง (custom labels)
- 3 ชั้น: user_labels > ภาษา > ค่า default ของระบบ
- ใช้ตัวแปรที่อนุญาตเท่านั้น ({n}, {layer}, {price}) จำกัดความยาว ~80 ตัวอักษร
- แสดงผ่าน textContent / esc() เสมอ ห้าม innerHTML
- label_registry กำหนด key ที่ editable กับ locked (disclaimer ล็อก)
- เป็น capability custom_labels ผูกกับ Tier
- ค่าเริ่มต้นเป็นกลาง เช่น "ไม้ที่ถึงเป้ากำไรที่คุณตั้งไว้: {n} ไม้"

## 10. ที่เก็บข้อมูล สำรอง ซิงก์
- ข้อมูลหลักใน IndexedDB ขอ navigator.storage.persist()
- Storage Adapter เดียวสำหรับทุกโมดูล: local, Google Drive, OneDrive, server
- Google Drive: ใช้ appDataFolder (scope drive.appdata, non-sensitive, โฟลเดอร์ซ่อน)
- OneDrive: Apps/{ชื่อแอป} ผ่าน Files.ReadWrite.AppFolder (บัญชีส่วนตัว ผู้ใช้เห็นไฟล์ได้)
- เข้ารหัสไฟล์สำรองในเครื่องก่อนอัปโหลด (AES-GCM ผ่าน Web Crypto) ด้วยรหัสผ่านผู้ใช้ + รหัสกู้คืน
- สำรองอัตโนมัติ: หลังมีการเปลี่ยนแปลง (debounce) และตอนเปิดแอป ไม่สัญญาว่าสำรองตอนปิดแอป
- ปุ่มส่งออก/นำเข้า JSON ยังคงอยู่ (ทางสำรองสำหรับ iPhone/Safari ที่ File System Access อาจไม่ครอบคลุม ต้องตรวจ)
- แบนเนอร์เตือนเมื่อไม่ได้สำรองเกิน 7 วัน
- ซิงก์หลายเครื่อง = เฟสหลัง ใช้เหตุการณ์ append-only
- ผู้ใช้เดิมของ GoldLot2L: นำเข้าไฟล์ JSON v2 (key goldlot2l.v2) พร้อม migration

## 11. การอัปเดตอัตโนมัติ

| ส่วน | วิธี |
|---|---|
| ตัวแอป (service worker) | ตรวจเวอร์ชันเมื่อเปิดแอป ติดตั้งแล้วกระตุ้นรีโหลดตอนเปิดแอปครั้งถัดไป หรือตอนแอปว่างและไม่มีฟอร์มค้าง ไม่รีโหลดกลางการกรอก |
| ธีมตามเทศกาล | เป็นข้อมูล (tokens + valid_from/to) ดึงตอนเปิดแอป ไม่ต้องออกแอปใหม่ ผู้ใช้เลือกเปิด/ปิดสลับอัตโนมัติ |
| ATH/ข้อมูลอ้างอิง | stale-while-revalidate: แสดงของเดิมก่อน ตรวจเวอร์ชันในพื้นหลัง ขึ้นการ์ด "ยอมรับ" |
| Subscription | ฝั่งเซิร์ฟเวอร์ (Stripe) ทำงานเองแม้ไม่เปิดแอป |

ข้อควรจำ: Periodic Background Sync ไม่รองรับ Safari/Firefox และเบราว์เซอร์เป็นผู้กำหนดเวลา จึงไม่พึ่งเป็นกลไกหลัก
ความปลอดภัยในการอัปเดต: staged rollout 5% -> 25% -> 100%, สำรองก่อน migration ทุกครั้ง, เก็บเวอร์ชันก่อนหน้าเพื่อย้อนกลับ, ทดสอบบน iPhone จริง

## 12. การเรียกเก็บเงิน
- Stripe Billing (ขายผ่านเว็บ) บัตรสำหรับตัดอัตโนมัติ PromptPay ไม่ตัดซ้ำอัตโนมัติ ต้องเตือนล่วงหน้า (7 วัน และ 1 วัน)
- webhook (ตรวจลายเซ็น + idempotent) อัปเดตตาราง subscriptions ; entitlement อ่านจากตารางนี้
- ตั้ง Smart Retries ; invoice.payment_failed -> แจ้งผู้ใช้ให้แก้วิธีจ่าย
- grace period 7-14 วัน (ใช้งานได้ตามปกติ + ข้อความเตือนอ่านง่าย) แล้วลดเป็นสิทธิ์ฟรีแบบอ่าน/ส่งออกได้
- signed entitlement token อายุ ~30 วัน เก็บในเครื่อง ตรวจลายเซ็นออฟไลน์ ต่ออายุเมื่อออนไลน์
- รายได้เสริม: รายปี (ลด ~15-20%), ทดลองใช้ฟรี, lifetime จำกัดเวลา, แพ็กธีมซื้อขาด
- ธีม: ไม่ขาย subscription $1.99 แยก เสนอแพ็กซื้อขาด หรือรวมใน Tier
- ถ้าขึ้นสโตร์: ตรวจนโยบายการจ่ายเงินของ Google Play / Apple ก่อน (อาจกระทบราคาและค่าธรรมเนียม)
- เผยแพร่: PWA ก่อน -> Android ผ่าน TWA (ค่าสมัคร Play ครั้งเดียว) -> iOS ภายหลังเมื่อคุ้ม (สมาชิกนักพัฒนา Apple รายปี และต้องใช้ Mac)

## 14. ความปลอดภัย ความเป็นส่วนตัว กฎหมาย (ต้องให้ผู้เชี่ยวชาญตรวจ)
ความปลอดภัย
- แก้ XSS: esc() ครอบข้อความผู้ใช้ทั้งหมด (เช่น e.note ใน capLog) ตรวจโครงสร้างไฟล์นำเข้า
- CSP, rate limit ที่ login/API, Cloudflare เป็นด่านหน้า, รหัสผ่านแบบ hash ที่เหมาะสม, MFA สำหรับ admin
- audit log เหตุการณ์สำคัญ ; สำรอง Postgres อัตโนมัติ + ทดสอบกู้คืนทุกไตรมาส
- ตรวจสอบ secrets ก่อน commit (ไม่เก็บคีย์ใน repo)

ความเป็นส่วนตัว
- เก็บข้อมูลให้น้อยที่สุด ธุรกรรมอยู่ในเครื่องผู้ใช้
- นโยบายความเป็นส่วนตัว, ขอลบ/ส่งออกข้อมูลได้, ข้อมูลบุคคลที่สาม (ลูกหนี้) ใช้ชื่อเล่น
- ผู้เยาว์: PDPA ไทยถือผู้เยาว์ต่ำกว่า 20 ปี ต่ำกว่า 10 ปีต้องได้รับความยินยอมจากผู้ปกครอง ช่วง 10-20 ปีโดยทั่วไปต้องได้ความยินยอมทั้งสองฝ่ายยกเว้นกรณีที่ผู้เยาว์ทำเองได้ตามกฎหมาย => ใช้บัญชีผูกผู้ปกครอง เด็กไม่เป็นผู้จ่ายเงิน
- ต่างประเทศ: เกณฑ์อายุ/ข้อมูลข้ามพรมแดน/ภาษีดิจิทัลต่างกัน ใช้ country_rules และเปิดทีละประเทศ

กฎหมายการเงิน
- วางตำแหน่งเป็นสมุดบันทึก ใช้ถ้อยคำเป็นกลาง ใส่ disclaimer ล็อก ไม่เชื่อมบัญชี/ไม่ส่งคำสั่งซื้อขาย
- ก่อนเก็บเงิน ให้ปรึกษาผู้เชี่ยวชาญกฎหมายตลาดทุน/ก.ล.ต. โดยแนบภาพหน้าจอและคำอธิบายฟีเจอร์
- ไม่ใช้ affiliate โบรกเกอร์/แพลตฟอร์มลงทุน (ขัดจุดยืน)

## 18. คำถามเปิดที่ยังต้องตัดสินใจ
