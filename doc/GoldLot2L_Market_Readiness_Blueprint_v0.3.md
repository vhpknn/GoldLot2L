วันที่: 11 พ.ย. 2026 | สถานะ: ร่างหลังการค้นหา ยังไม่ผ่านการตรวจโดยทนาย นักบัญชี หรือที่ปรึกษาท้องถิ่น
ไฟล์คู่กัน: GoldLot2L_Price_Book_Example.xlsx (ตารางราคาต่อประเทศพร้อมสูตร แก้ตัวเลขสมมติได้)

> **อ่านก่อน**
> 1. เอกสารนี้ไม่ใช่คำปรึกษากฎหมาย ภาษี การเงิน หรือการลงทุน
> 2. ข้อมูลกฎหมายส่วนใหญ่มาจากบทความของบริษัทที่ปรึกษาและบล็อก ยกเว้นเรื่อง OFAC, FCA, กฎ geo-blocking ของ EU และหน้านโยบาย/ค่าธรรมเนียมของ Google/Apple/Meta ที่มาจากเว็บของหน่วยงานหรือแพลตฟอร์ม กฎและค่าธรรมเนียมเปลี่ยนเร็ว
> 3. คะแนนความยาก อันดับ และ **ตัวคูณราคา ภาษี ค่าธรรมเนียมเว็บ ต้นทุนผันแปร และเป้าสุทธิ ในข้อ 10 เป็นค่าสมมติของผู้ร่างเพื่อสาธิต** ไม่ใช่ข้อเท็จจริงหรือข้อเสนอราคาขายจริง
> 4. ไม่มีสื่อโปรโมต ราคา หรือโครงสร้างการขายใดในเอกสารนี้ที่รับรองว่าถูกกฎหมายทุกประเทศ ต้องให้ผู้เชี่ยวชาญท้องถิ่นอนุมัติเป็นรายประเทศ
> 5. สิ่งที่ยังไม่ได้ตรวจ ระบุว่า "ยังไม่ได้ตรวจ" ไม่ได้เดา

## 2. เงื่อนไขพื้นฐานก่อนเปิดประเทศใด
- ระบบ i18n (ไฟล์ภาษา, Intl, RTL ถ้าจำเป็น)
- `asset_config` ตั้งหน่วย สกุลเงิน ทศนิยมต่อสินทรัพย์
- `country_rules` (อายุขั้นต่ำ ผู้ปกครอง ภาษา สกุลเงิน สถานะการเปิดประเทศ ตัวแทนท้องถิ่น ข้อกำหนดเก็บข้อมูล สถานะโปรโมต **ช่องทางขายที่อนุญาต**)
- `price_book` (ราคาต่อแพ็กเกจต่อประเทศ ต่อช่องทาง ดูข้อ 10.10)
- ระบบสิทธิ์กลาง (entitlement) รับสถานะสมาชิกจากทุกช่องทางผ่านบัญชีเดียว
- disclaimer ล็อก แปลโดยผู้เชี่ยวชาญ ; นโยบายความเป็นส่วนตัวแยกภูมิภาค
- ระบบบล็อกการสมัคร/จ่ายเงินตามประเทศ
- local-first ช่วยลดข้อมูลบนเซิร์ฟเวอร์ แต่บัญชีผู้ใช้ อีเมล สถานะสมาชิก ยังเป็นข้อมูลส่วนบุคคล

### 4.1 กลุ่ม A
**ไทย (ตลาดตั้งต้น)**: ภาษาไทย / บาททอง / THB ; ตัวอย่างแอปออมทองในประเทศ: เป๋าตัง Gold Wallet ขั้นต่ำ 0.05 บาททอง (แหล่งข้อมูลเป็นโพสต์ผู้ใช้) ; Stripe เริ่มให้บริการธุรกิจไทยตามบทความที่พบ ; PDPA ผู้เยาว์ต่ำกว่า 20 ปี ต่ำกว่า 10 ปีต้องผู้ปกครองยินยอม 10-20 ปีโดยทั่วไปต้องทั้งสองฝ่าย ; งานที่ต้องทำ: ผู้เชี่ยวชาญตลาดทุน/ก.ล.ต. ตรวจถ้อยคำและการเก็บเงิน ; ยังไม่ได้ตรวจ: ภาษีบริการดิจิทัล การจดทะเบียนธุรกิจ กฎโฆษณาการเงินของไทย

**ญี่ปุ่น** (ยังไม่ได้ตรวจ localization): ญี่ปุ่น / กรัม / JPY ; วัฒนธรรมออมทองรายเดือน ; คำแปลต้องให้เจ้าของภาษาตรวจ ; ยังไม่ได้ตรวจ APPI
**สหราชอาณาจักร**: อังกฤษ / กรัม-ออนซ์ / GBP ; Royal Mint DigiGold, BullionVault ; นโยบาย UK GDPR ; **การโปรโมตเป็นประเด็นเข้มของ FCA (ข้อ 11)**

### 4.3 กลุ่ม C
**จีน**: ทางเลือก A เซิร์ฟเวอร์นอกจีน (ไม่ต้อง ICP แต่ช้า/ไม่เสถียร/เข้า Google Play ไม่ได้) ; B เซิร์ฟเวอร์ในจีน (ต้อง ICP + นิติบุคคลในจีน ใบอนุญาตพาณิชย์ถ้าเก็บเงิน) ; C WeChat Mini Program/สโตร์จีน (เขียนใหม่ ต้องมีนิติบุคคลหรือพันธมิตร จดแจ้งแอป) ; PIPL ใช้กับบริการที่ประมวลผลข้อมูลคนในจีนแม้ให้บริการจากต่างประเทศ โทษสูงสุด 50 ล้านหยวน ; **Google Play ไม่ใช่ช่องทางหลักในจีน** (ต้องตรวจยืนยัน) แอป Android ในจีนแจกผ่านหลายสโตร์ท้องถิ่น ; ยังไม่ได้ตรวจ: การเข้าถึง Stripe/Cloudflare/Drive จากในจีน, เงื่อนไข WeChat Pay/Alipay ; ข้อเสนอ: ทดลอง A วัดความต้องการ แล้วค่อยพิจารณา B/C กับพันธมิตร
**รัสเซีย**: 152-FZ ต้องเก็บข้อมูลพลเมืองรัสเซียในฐานข้อมูลในประเทศ และแจ้งก่อนส่งข้อมูลข้ามพรมแดน ; มีมาตรการคว่ำบาตรสหรัฐฯ เฉพาะภาคส่วน ; ไม่เปิดในระยะแรก

### 4.4 กลุ่ม D
ประเทศที่ถูกคว่ำบาตรทั้งประเทศตาม OFAC (เช่น คิวบา อิหร่าน เกาหลีเหนือ ซีเรีย) และบางภูมิภาค (เช่น ไครเมีย โดเนตสก์ ลูฮันสก์) ; บล็อกการสมัครและการจ่ายเงิน ; ตรวจรายชื่อ SDN ตามคำแนะนำทนาย ; รายการเปลี่ยนตามเวลา

## 8. ประตูตรวจก่อนเปิดทุกประเทศ (Market Launch Gate)
ต้องผ่านครบก่อนเปลี่ยนสถานะเป็น "เปิด"
1. [ ] ทนาย/ที่ปรึกษาท้องถิ่นตรวจ: ถ้อยคำการลงทุน, สมุดบันทึก vs คำแนะนำ, การเก็บเงิน
2. [ ] กฎข้อมูลส่วนบุคคล: เก็บในประเทศ? จดทะเบียน? ตัวแทน? โอนข้อมูลข้ามพรมแดน?
3. [ ] ผู้เยาว์: เกณฑ์อายุ ความยินยอมผู้ปกครอง
4. [ ] นโยบายความเป็นส่วนตัวและข้อกำหนดใช้งาน แปลโดยผู้เชี่ยวชาญ
5. [ ] ระบบจ่ายเงินที่ถูกกฎหมาย + ภาษีบริการดิจิทัล
6. [ ] ภาษา: เจ้าของภาษาตรวจข้อความเกี่ยวกับเงิน ทดสอบตัวเลข/วันที่/สกุลเงิน
7. [ ] หน่วยทองและสกุลเงิน: ตั้ง asset_config ถูกต้อง ทดสอบการคำนวณ
8. [ ] แหล่งราคา/ATH: ผู้ใช้กรอกเองได้ ค่าแนะนำใช้แหล่งที่เผยแพร่ซ้ำได้
9. [ ] การเข้าถึง: ทดสอบจากเครือข่ายในประเทศนั้นจริง
10. [ ] การสนับสนุนผู้ใช้: ช่องทางและภาษา
11. [ ] บล็อก/ปลดบล็อกตาม country_rules ทดสอบแล้ว
12. [ ] ย้อนกลับ: ปิดประเทศได้เร็วโดยไม่กระทบประเทศอื่น
13. [ ] สื่อโปรโมตชุดแรกผ่านการอนุมัติตามข้อ 11.6 (ทะเบียนข้อความ + ผู้อนุมัติ)

16. [ ] **ราคา**: มีรายการใน `price_book` ผ่านเกณฑ์รายได้สุทธิขั้นต่ำ ; ผู้เชี่ยวชาญตรวจเรื่องภาษีที่รวมในราคาและกฎการตั้งราคาตามประเทศ (เช่น EU) ; ตั้งแผนรับมือผู้ใช้ย้ายประเทศ/ใช้ VPN

## 9. ช่องทางขายสมาชิก: เว็บ vs สโตร์ (ใหม่ใน v0.3)

### 9.1 ทางเลือก
- **A. เว็บอย่างเดียว** (Stripe หรือผู้ให้บริการอื่น) ใช้กับ PWA และแอป TWA ที่เปิดเว็บ
- **B. สโตร์อย่างเดียว** (Google Play Billing / Apple In-App Purchase) ใช้กับแอปที่ลงสโตร์
- **C. ผสม (แนะนำ)** ขายได้ทั้งสองทาง มีระบบสิทธิ์กลางตัวเดียวอ่านสถานะจากทุกช่องทาง ผู้ใช้เข้าสู่ระบบบัญชีเดียว ใช้บริการตัวกลางที่รองรับหลายช่องทางหรือเขียนเองก็ได้ (ผู้ให้บริการกลางประเภทนี้มีหลายราย ยังไม่ได้เปรียบเทียบ ต้องเทียบค่าบริการก่อนเลือก)

### 9.3 ผลต่อการจ่ายเงินและภาษีในคลื่น 2-6
- **ช่วยได้**: การจ่ายเงินท้องถิ่น (ลดงานต่อระบบจ่ายเงินรายประเทศ) และงานภาษีบริการดิจิทัลที่สโตร์รับผิดชอบเก็บ (ต้องยืนยันรายประเทศ)
- **ไม่ช่วย**: ข้อมูลส่วนบุคคลบนเซิร์ฟเวอร์เรา (PIPL, 152-FZ, เก็บข้อมูลในประเทศ) การจดทะเบียนท้องถิ่น (PSE, ICP) กฎ financial promotion และถ้อยคำ ภาษา หน่วย
- **จีน**: ไม่ใช่ Google Play เป็นหลัก ต้องแยกโครงการ
- **เมื่อรายได้เล็ก**: ส่วนต่างค่าธรรมเนียมเว็บกับสโตร์ไม่ได้ชี้ขาดเสมอ ดูข้อ 10 ที่ใช้ตัวเลขสมมติเปรียบเทียบ

### 9.5 กติกาการออกแบบสำหรับช่องทางผสม
1. **บัญชีเดียว สิทธิ์เดียว**: ผู้ใช้ล็อกอินบัญชีเดียวกันทุกช่องทาง ระบบสิทธิ์กลางอ่านสถานะจาก Stripe/Play/Apple
2. **ผู้ซื้อผ่านสโตร์ ต้องจัดการสมาชิกผ่านสโตร์** (ยกเลิก เปลี่ยนแพ็กเกจ) แอปแสดงข้อความนำทางที่ถูกต้อง
3. **ไม่ลิงก์ไปจ่ายเงินนอกสโตร์** ในแอปสโตร์ จนกว่าตรวจแล้วว่า storefront นั้นอนุญาต
4. **ราคาสอดคล้องกัน**: นโยบายความต่างราคาเว็บ vs สโตร์ต้องตัดสินใจ (บางสโตร์อาจไม่ให้เว็บถูกกว่าในบางกรณี ยังไม่ได้ตรวจ)
5. **ไม่ให้ผู้ใช้จ่ายซ้ำ**: ตรวจสิทธิ์ที่มีอยู่ก่อนเสนอซื้อ
6. **คืนเงิน**: ตามช่องทางที่ซื้อ ทำคู่มือฝ่ายสนับสนุน
7. **ข้อมูลสิทธิ์ใน token ออฟไลน์** (ตาม Blueprint v0.2) ใช้ได้ทุกช่องทาง
8. **ทดสอบครบ**: ซื้อใหม่ ต่ออายุ ล้มเหลว ยกเลิก คืนเงิน ย้ายอุปกรณ์ เปลี่ยนประเทศบัญชีสโตร์

### 9.6 เกณฑ์เลือกช่องทางต่อประเทศ
- วิธีจ่ายเงินที่คนในประเทศใช้จริง (ผู้ให้บริการรองรับหรือไม่)
- ความยากภาษีและใบกำกับภาษี
- ต้นทุนสุทธิต่อผู้จ่ายเงิน (ข้อ 10)
- กติกาสโตร์ (ช่องทางจ่ายเงินภายนอก)
- ความพร้อมของแอป (มีแอปบนสโตร์ในประเทศนั้นหรือไม่)
- ภาระด้านกฎหมายที่เปลี่ยนตามช่องทาง

## 10. ราคาต่อประเทศ (ใหม่ใน v0.3)

### 10.1 หลักการ
1. ตั้งราคาจาก **รายได้สุทธิขั้นต่ำต่อผู้จ่ายเงิน** ก่อน แล้วค่อยปรับตามกำลังซื้อ (ไม่ใช่ตั้งตามลำดับคลื่น)
2. ใช้ **3-4 ระดับราคา (bands)** ไม่ตั้งทีละประเทศ เพื่อลดความซับซ้อนและช่องว่างราคาที่ใหญ่เกิน
3. มี **ราคาต่ำสุด** ที่ผ่านเป้ารายได้สุทธิ ไม่ลดต่ำกว่านั้นแม้ประเทศนั้นกำลังซื้อต่ำ
4. คงราคาเดิมให้ผู้สมัครเก่า (grandfathering) เมื่อปรับราคา
5. เก็บราคาเป็นข้อมูล (`price_book`) ไม่ฝังในโค้ด

### 10.2 สูตร
- สุทธิ (เว็บ) = ราคา / (1 + ภาษีที่รวมในราคา) - (ราคา x %เว็บ + ค่าคงที่เว็บ) - ต้นทุนผันแปร
- สุทธิ (สโตร์) = ราคา / (1 + ภาษีที่รวมในราคา) x (1 - %สโตร์) - ต้นทุนผันแปร
- เป้าสุทธิ = สัดส่วนเป้า x ราคาฐาน
- ราคาต่ำสุด = ราคาที่ทำให้ทั้งสองช่องทางไม่ต่ำกว่าเป้า (ปัดขึ้นเป็นราคา .49 หรือ .99)

### 10.9 ข้อควรระวัง
**การใช้ VPN / ที่อยู่ปลอม**: ถ้าราคาต่างกันมาก คนจะสมัครราคาถูกจากประเทศอื่น ลดด้วย (ก) ช่องว่างราคาไม่ใหญ่ (ข) ตรวจประเทศบัตร/ที่อยู่เรียกเก็บเงินกับ IP (ค) ใช้ช่องทางสโตร์ซึ่งผูกกับประเทศบัญชีสโตร์ (ง) ใช้เครื่องมือตรวจความเสี่ยงของผู้ให้บริการจ่ายเงิน
**EU geo-blocking (ต้องให้ทนาย EU ตรวจ)**:
- EU ห้ามเลือกปฏิบัติต่อลูกค้าตามสัญชาติหรือที่อยู่ ผู้ค้าต้องไม่ปฏิเสธการขายให้ลูกค้าจากประเทศสมาชิกอื่นหรือขายในเงื่อนไขต่างกันโดยไม่มีเหตุผล
- แต่ **ตั้งราคาต่างกันรายประเทศในเว็บของแต่ละประเทศไม่ผิดโดยตัวมันเอง** ; ห้ามเปลี่ยนเส้นทางลูกค้าไปเว็บประเทศตนโดยไม่ได้รับความยินยอม
- ขอบเขตการบังคับใช้กับผู้ค้านอก EU ที่ขายให้ผู้อยู่ใน EU: **ผู้ร่างยังไม่ได้ยืนยัน** ต้องให้ทนาย EU ตรวจ
- ผลต่อเรา: ในกลุ่ม EU ไม่ควรล็อกราคาตามที่ตั้งแบบเข้มเพื่อกัน VPN เกินกว่าที่กฎอนุญาต ต้องมีทางให้ผู้ใช้เลือก/เห็นราคาของประเทศอื่นตามที่กฎกำหนด ผู้ร่างยังไม่ทราบรายละเอียดการปฏิบัติ
**ภาษีรวม/ไม่รวมในราคาที่แสดง**: ต่างกันตามประเทศ ต้องแสดงราคาตามธรรมเนียมและกฎผู้บริโภคของประเทศนั้น
**ผู้ใช้ย้ายประเทศ**: ราคาอาจเปลี่ยนเมื่อต่ออายุ ต้องกำหนดนโยบาย (คงราคาเดิมหรือเปลี่ยนเมื่อต่ออายุ) และสื่อสารล่วงหน้า
**ความรู้สึกเป็นธรรม**: อธิบายนโยบายราคาตามประเทศตรงๆ ไม่ใช้ข้อความที่ชวนเข้าใจผิด
**สกุลเงิน**: บางประเทศสกุลเงินผันผวน (เช่น ตุรกี) ต้องมีรอบทบทวนราคาและกฎป้องกันราคาเปลี่ยนกะทันหัน
**อัตราค่าธรรมเนียมจริง**: อัตราเว็บและสโตร์รายประเทศอาจต่างจากที่สมมติ ตรวจก่อนใช้
**Stripe Adaptive Pricing**: Stripe มีเครื่องมือแสดงราคาเป็นสกุลเงินท้องถิ่นใน 150+ ประเทศ ผู้ร่างยังไม่ได้ตรวจเงื่อนไขและค่าธรรมเนียมของเครื่องมือนี้

### 10.10 โครงสร้างข้อมูล `price_book` (ร่าง)
`price_book(id, plan_code, country, band, currency, amount_minor_units, tax_inclusive[bool], tax_rate_note, channel[web|play|apple], effective_from, effective_to, min_net_target_usd, approved_by, approved_at, note)`
- แยกแถวต่อช่องทาง เพราะราคาและค่าธรรมเนียมต่างกันได้
- ผู้ดูแลแก้ผ่านหน้า Admin ; ทุกการเปลี่ยนราคาต้องมีผู้อนุมัติและวันที่มีผล
- เก็บ `grandfathered_until` ในตารางสมาชิก ไม่แก้ราคาเดิมของผู้สมัครเก่า

### 10.11 กระบวนการตั้ง/เปลี่ยนราคา
1. กำหนดราคาฐานและเป้าสุทธิ (ภายในบริษัท)
2. ตั้ง bands ตามกำลังซื้อ/ต้นทุน/คู่แข่ง (ข้อมูลจริง ไม่ใช้ตัวคูณสมมติ)
3. คำนวณราคาต่ำสุดต่อช่องทางต่อประเทศ ด้วยอัตราจริงที่ตรวจแล้ว
4. ผู้เชี่ยวชาญตรวจภาษีและกฎราคา (รวม EU)
5. ทดลองในประเทศเดียว วัดอัตราสมัคร รายได้สุทธิ ความถี่คืนเงิน
6. ปรับ ทบทวนรายไตรมาส บันทึกผลทุกครั้ง

## 11. แผนโปรโมตแบบปลอดภัยต่อกฎหมาย

### 11.1 เป้าหมายและหลักการ
เป้าหมาย: ทำให้ผู้คนในแต่ละประเทศรู้จักและเข้าใจแอปในฐานะสมุดบันทึก ผ่านตัวอย่างที่คุ้นเคย โดยลดความเสี่ยงถูกตีความว่าชักชวนให้ซื้อ/ลงทุนสินทรัพย์ หรือให้คำแนะนำ
1. โปรโมตเครื่องมือ ไม่โปรโมตสินทรัพย์
2. ตัวอย่างเป็นสมมติเสมอ ไม่ใช้ราคาจริงล่าสุดหรือผลตอบแทนย้อนหลังเป็นจุดขาย
3. ไม่มีผลตอบแทน ไม่มีคำรับประกัน ไม่มีการเปรียบเทียบเชิงแนะนำ
4. ไม่มีปุ่มพาไปซื้อ ไม่ทำ affiliate กับโบรกเกอร์/แพลตฟอร์มลงทุน
5. ใช้เฉพาะข้อความในทะเบียนข้อความที่อนุมัติ (claims register)
6. เปิดประเทศก่อน โปรโมตทีหลัง
7. ไม่ทำการตลาดมุ่งเป้าเด็กโดยตรง สื่อสำหรับเด็กมุ่งผู้ปกครองและการเรียนรู้
8. เก็บหลักฐานการอนุมัติ ถอดสื่อได้เร็ว

### 11.5 หมายเหตุรายประเทศ/แพลตฟอร์ม (จากหน้าทางการ ณ วันที่ค้น)
**สหราชอาณาจักร (FCA)**: กฎ financial promotion ใช้กับทุกช่องทางรวมโซเชียล ต้องเป็นธรรม ชัดเจน ไม่ทำให้เข้าใจผิด ; ผู้ที่ไม่ได้รับอนุญาต เช่น อินฟลูเอนเซอร์ ที่โปรโมตผลิตภัณฑ์ที่อยู่ภายใต้การกำกับโดยไม่ได้รับการอนุมัติ อาจมีความผิดทางอาญา ; ยังไม่ทราบว่าแอปสมุดบันทึกเข้าข่ายหรือไม่ -> ทนาย UK ตัดสิน
**Google Ads**: ต้องปฏิบัติตามนโยบาย financial products and services และกฎท้องถิ่นของประเทศที่ลงโฆษณา ; เคยประกาศข้อกำหนดการตรวจสอบนักโฆษณาด้านบริการการเงินในหลายประเทศ เช่น ฝรั่งเศส เยอรมนี อินโดนีเซีย สเปน บราซิล อินเดีย โปรตุเกส ออสเตรเลีย สิงคโปร์ ไต้หวัน (ประกาศปี 2022 อาจเปลี่ยน ต้องตรวจหน้านโยบายล่าสุด)
**Meta**: ผู้โฆษณาผลิตภัณฑ์/บริการทางการเงินต้องยืนยันตัวตนทางธุรกิจ/บุคคล และแสดงว่าได้รับอนุญาตจากหน่วยงานกำกับที่เกี่ยวข้อง (ตามหน้านโยบายของ Meta) ; **ผู้ร่างยังไม่ได้ยืนยัน** ว่าประเทศใดบ้างที่ต้องตรวจสอบ และเนื้อหาให้ความรู้ทางการเงินทั่วไปเข้าข่ายหรือไม่ -> ต้องอ่านหน้านโยบายล่าสุดและทดลองส่งจริง ไม่ทราบว่า Meta จะจัดแอปเราเป็นประเภทใด
**ประเทศอื่น**: ยังไม่ได้ตรวจกฎโฆษณาและ financial promotion ของไทย ญี่ปุ่น สิงคโปร์ มาเลเซีย ตุรกี เวียดนาม UAE ซาอุฯ EU รายประเทศ อินโดนีเซีย จีน รัสเซีย

### 11.6 กระบวนการอนุมัติสื่อ (Claims Governance)
1. ทะเบียนข้อความ: ประเทศ ภาษา วันที่ ผู้เสนอ ผู้ตรวจ สถานะ หลักฐานรองรับ
2. เกณฑ์ต้องห้าม: ผลตอบแทน การรับประกัน การเปรียบเทียบเชิงแนะนำ การชักชวนให้ซื้อ/ขาย การอ้างสถิติผลงานผู้ใช้ การอ้างว่าได้รับการรับรองจากหน่วยงาน
3. ขั้นตอน: ผู้เสนอ -> ตรวจภายใน -> ทนาย/ที่ปรึกษาท้องถิ่น -> อนุมัติ -> เผยแพร่ (ห้ามเผยแพร่ข้อความนอกทะเบียน)
4. เจ้าของภาษาตรวจ ห้ามใช้ตัวแปลอัตโนมัติอย่างเดียวกับข้อความเรื่องเงิน
5. ทบทวนทุกไตรมาสหรือเมื่อกฎเปลี่ยน
6. ถอดสื่อได้เร็ว มีเจ้าของงานชัดเจน บันทึกการถอด
7. เก็บสำเนาสื่อ ช่องทาง วันที่ เวอร์ชัน
8. ข้อความ locked ในแอป (disclaimer, ป้ายตัวอย่างสมมติ)
9. **ตรวจข้อความเกี่ยวกับราคาและช่องทางขาย** (เช่น คำว่า "ราคาพิเศษ" "ฟรีตลอดชีพ") ให้ตรงกับ price_book และกฎผู้บริโภคของประเทศนั้นด้วย

### 11.7 แนวทางสัญญากับอินฟลูเอนเซอร์/พันธมิตร (ให้ทนายตรวจ)
ใช้เฉพาะสคริปต์ที่อนุมัติ ; ห้ามพูดผลตอบแทน ราคาตลาด หรือแนะนำซื้อ/ขายสินทรัพย์ ; เปิดเผยความสัมพันธ์ทางการค้าตามกฎประเทศ ; แสดง disclaimer ห้ามตัดต่อให้หาย ; ส่งงานให้ตรวจก่อนเผยแพร่ มีสิทธิ์สั่งถอดทันที ; ห้ามกำหนดเป้าหมายผู้เยาว์ ; ห้ามสื่อให้เข้าใจว่าแอปเป็นผู้ให้คำแนะนำหรือได้รับอนุญาตทางการเงิน ; ตรวจว่ากฎท้องถิ่นให้เรารับผิดชอบการสื่อสารของพันธมิตรหรือไม่ และมีระบบตรวจสอบรองรับ

### 11.8 วัดผลและรับมือ
วัด: ผู้เข้าชมหน้าสอนใช้ ติดตั้ง/เปิดใช้ครั้งแรก การบันทึกครั้งแรก ใช้ต่อเนื่อง อัพเกรดสมาชิก ; ไม่ใช้ผลตอบแทนผู้ใช้เป็นสื่อ ; เก็บข้อมูลวิเคราะห์น้อยที่สุดตามกฎประเทศ ; ทดลองโฆษณาเล็กก่อน
รับมือ: ถูกปฏิเสธโฆษณา -> หยุดข้อความนั้นทุกช่องทาง ตรวจเหตุผล แก้ในทะเบียน ; หนังสือเตือน/ข้อร้องเรียน -> ถอดสื่อ เก็บหลักฐาน แจ้งทนาย ; อินฟลูเอนเซอร์นอกสคริปต์ -> สั่งถอด ใช้สิทธิ์ตามสัญญา ; กฎเปลี่ยน -> ตั้งสถานะ "หยุดโปรโมต" ใน country_rules

## 13. ความเสี่ยง
| ความเสี่ยง | ผลกระทบ | วิธีลด |
|---|---|---|
| กฎเปลี่ยนหลังเปิด | สูง | ตรวจกฎทุกไตรมาส ; country_rules ปรับสถานะได้เร็ว |
| แหล่งข้อมูลกฎหมายส่วนใหญ่ไม่เป็นทางการ | สูง | ทนายท้องถิ่นยืนยันก่อนเปิดทุกประเทศ |
| คำแปลผิดในข้อความเรื่องเงิน | กลาง-สูง | เจ้าของภาษาตรวจ ; ข้อความ locked |
| ถูกบล็อก/เข้าถึงไม่ได้ | สูง | ทดสอบจากเครือข่ายในประเทศ ; ไฟล์สำรองเป็นค่าเริ่มต้น |
| เปิดหลายประเทศเกินกำลังสนับสนุน | กลาง | ทยอยเปิด |
| ถูกตีความเป็นคำแนะนำการลงทุน | สูง | ถ้อยคำเป็นกลาง ตรวจกฎท้องถิ่น |
| สื่อโปรโมตถูกตีความเป็น financial promotion | สูง | ทะเบียนข้อความ ทนายอนุมัติ |
| อินฟลูเอนเซอร์/พันธมิตรพูดนอกสคริปต์ | สูง | สัญญา สคริปต์ ตรวจก่อนเผยแพร่ |
| โฆษณาถูกปฏิเสธ/บัญชีถูกจำกัด | กลาง | ทดลองเล็ก ไม่พึ่งช่องทางเดียว |
| ตัวอย่างในแอปถูกอ่านเป็นคำแนะนำ | กลาง-สูง | ป้ายสมมติ locked ตัวเลขสมมติ |

| **ใช้ VPN/ที่อยู่ปลอมซื้อราคาถูก** | กลาง | ช่องว่างราคาไม่ใหญ่ ตรวจประเทศบัตร/ที่อยู่ ใช้สโตร์ |

| **ค่าธรรมเนียมสโตร์/เว็บเปลี่ยนจนราคาไม่คุ้ม** | กลาง | ทบทวน price_book เมื่อนโยบายเปลี่ยน |

## 14. สิ่งที่ยังไม่รู้ (ต้องตรวจก่อนอัปเดตเป็น v0.4)
1. กฎข้อมูลส่วนบุคคลและ localization ของ สิงคโปร์ มาเลเซีย ญี่ปุ่น UAE
2. ข้อสรุปเรื่องเวียดนาม (แหล่งข้อมูลขัดกัน)
3. เงื่อนไขผู้ให้บริการจ่ายเงินแต่ละประเทศ (WeChat Pay/Alipay/UPI/e-wallet อาเซียน) ทั้งช่องทางเว็บและสโตร์
4. การเข้าถึง Google Drive, Cloudflare, Stripe จากแต่ละประเทศ
5. กฎการโฆษณาและ financial promotion ของแต่ละประเทศ รวมไทย
6. แพลตฟอร์มโฆษณาจะจัดแอปสมุดบันทึกเป็นผลิตภัณฑ์การเงินหรือไม่
7. แอปแบบนี้เข้าข่ายผลิตภัณฑ์/บริการที่ถูกกำกับ (เช่น ใน UK) หรือไม่
8. นโยบายสโตร์ต่อแอปที่ห่อเว็บ (TWA) และการขายสมาชิกในแอป แยกตามประเทศ ; ว่า TWA ต้องใช้ Play Billing หรือไม่ ; นโยบายล่าสุดของ Apple เรื่องลิงก์จ่ายเงินภายนอกต่อประเทศ
9. ภาษีบริการดิจิทัล (VAT/GST) อัตราจริงรายประเทศ และสโตร์เก็บ/นำส่งแทนหรือไม่ในแต่ละประเทศ
10. อัตราค่าธรรมเนียม Stripe รายประเทศ และเงื่อนไข Adaptive Pricing
11. ข้อมูลกำลังซื้อ (PPP) และราคาคู่แข่งจริง เพื่อแทนที่ตัวคูณราคาสมมติ
12. กฎ EU geo-blocking ในทางปฏิบัติสำหรับแอปสมาชิกของผู้ค้านอก EU
13. ตัวเลขผู้ใช้ที่เทียบกันได้ระหว่างประเทศ
14. ค่าบริการและเงื่อนไขของผู้ให้บริการระบบสิทธิ์กลางข้ามช่องทาง (ยังไม่ได้เปรียบเทียบ)

## 15. สรุปสั้น
- **พร้อมก่อน**: ไทย แล้วสิงคโปร์ มาเลเซีย ญี่ปุ่น สหราชอาณาจักร (ต้องผ่านประตูตรวจ)
- **ต้องทำขั้นตอน**: EU อินโดนีเซีย ตุรกี อินเดีย UAE เวียดนาม ซาอุฯ ; **โปรเจกต์แยก**: จีน รัสเซีย ; **ไม่เปิด**: ประเทศถูกคว่ำบาตรทั้งประเทศ
- **ช่องทางขาย**: เว็บเป็นหลักตอนเริ่ม ; สโตร์เสริมตามประเทศ ; ระบบสิทธิ์กลางตัวเดียว ; สโตร์ช่วยเรื่องจ่ายเงิน/ภาษา แต่ไม่ช่วยเรื่องข้อมูลส่วนบุคคล ทะเบียนท้องถิ่น และการโปรโมต
- **ราคาต่อประเทศ**: ใช้ bands ไม่ตามคลื่น ; มีราคาต่ำสุดจากรายได้สุทธิ ; Look & Feel 0.99 ต่อเดือนไม่คุ้มผ่านเว็บตามค่าสมมติ ควรพิจารณา 1.49/รายปี/รวม Tier ; EU ต้องให้ทนายตรวจก่อน
- **โปรโมต**: ขายเครื่องมือจดบันทึก ไม่ขายสินทรัพย์ ; ตัวอย่างสมมติ ; ข้อความต้องอยู่ในทะเบียนที่ทนายอนุมัติ

*เอกสารนี้ควรทบทวนเมื่อมีผลตรวจทางกฎหมาย ภาษี หรือข้อมูลจริงเพิ่ม และเชื่อมกับ country_rules กับ price_book ใน Web App Blueprint v0.2*
